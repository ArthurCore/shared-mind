# DEV-021 benchmark evidence — 2026-08-11

This artifact contains two distinct phases. The pre-index diagnostic stopped at 46,622 entries and did not certify 100k. The post-index release-candidate run completed fresh history-heavy and hot-active 100k fixtures. History-heavy passed immediately; hot-active initially missed the 2-second target, then passed after a projection-only single-scan optimization with byte-identical output.

The full machine-readable manifests, all 50-sample arrays, hashes, query plans, and environment are in [dev-021-2026-08-11-macos-arm64.json](./dev-021-2026-08-11-macos-arm64.json).

## Pre-index diagnostic

The first run did not complete the 100,000-entry benchmark. Fixture generation was stopped at the required 10-minute cap after 46,622 committed ledger entries. It is retained as diagnostic evidence and does not claim that its 100k p95 requirement was met.

### Measurement boundary

- Host: Apple M3 Pro, 11 logical CPUs, 19,327,352,832 bytes RAM
- OS: macOS 15.0.1 arm64, Darwin 24.0.0
- Runtime: Python 3.10.14, SQLite 3.43.2
- Git HEAD: `9f04dcd0962a88a2f2a530e1783deb21ebd79d1b`
- The shared worktree contained concurrent uncommitted kernel changes, so these results are diagnostic evidence rather than release-baseline certification.
- Python 3.10.14 is below the project's Python 3.11 minimum and is an explicit conformance caveat.
- Context timing excludes fixture creation and uses 5 warmups, 50 samples, `perf_counter_ns`, and nearest-rank p95 with a 32,000-byte budget.

### Hot-active risk

The 10k hot-active context retained 16 history entries and omitted 9,984, so output size is bounded. Query work is not bounded: the plan scans `ledger` twice through SQLite JSON virtual tables, uses a union temp B-tree, and sorts again.

A profile attributed about 0.214 of 0.224 seconds to SQLite execution. A simple 10x extrapolation ranges from 1.332 seconds using the quiet-run p95 to 2.237 seconds using the profiled wall time. That range crosses the 2-second target, so NFR-008 remains at risk and is not certified without a completed 100k run.

### Structural performance contract

`tests/test_benchmark_performance_contract.py` adds machine-independent gates requiring:

1. a persisted receipts index whose definition covers `idempotency_key`; and
2. a 5,000-row lookup plan using `SEARCH RECEIPTS`, never `SCAN RECEIPTS`.

The measured schema failed both gates. The tests deliberately assert query structure rather than host-specific timing. Concurrent production work may make this contract GREEN after this capture.
